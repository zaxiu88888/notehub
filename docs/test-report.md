## 4. 浏览器 UI 走查（已执行并截图确认）

**用户端**：首页题库筛选（简单 6 题 / 困难 0 题）→ 题单导航 → 登录/注册弹窗（dev 验证码自动回填+倒计时）→ 题单进度 1/6 → 题目详情 → 编辑笔记（Markdown 代码块渲染）→ 点赞 1→2→1 → 评论抽屉（楼中楼/回复@/编辑删除）→ 发评论 → 收藏（现场新建夹）→ 换题新建笔记 → 个人中心（资料回填与保存/我的笔记/收藏夹管理）→ 他人主页 → 消息中心（分类型角标/已读/删除）。

**管理端**：看板真实数据 → 题库管理新建（自动跳末页可见）与删除 → Markdown 批量导入「共 1 题成功 1 题」→ 题单类型显示「官方推荐」→ 分类树自动展开 → 用户管理封禁（aria-checked=true）与解封（API 复核 isBanned=0）。

## 5. 性能与安全自检

- **N+1**：笔记列表 SQL 次数 = 主表 1 + count 1 + 点赞 IN 1 + 收藏 IN 1，与页大小无关；评论楼中楼 1 条 IN 查询；收藏夹内容批量 1 条。
- **并发安全**：计数全部 `GREATEST(x+delta,0)` 原子更新；点赞/收藏唯一约束 + `INSERT IGNORE` 幂等。
- **鉴权**：所有 `/api/admin/**` 均有 `@NeedAdmin`；资源写操作校验归属（40301）；封禁用户按匿名处理。
- **上传**：后缀白名单（拒 svg）、5MB、UUID 重命名、路径穿越测试覆盖。
- **表达**：Markdown 默认不渲染原始 HTML（react-markdown），XSS 测试覆盖；SQL 全参数化。

## 6. 已知限制（记录待迭代）

1. 同一用户多个收藏夹重复收藏同一笔记时 `collect_count` 语义有偏差（已用「其他夹是否仍收」收敛，极端场景仍在），计划 I5 用独立统计表治理。
2. 消息投递失败仅记日志不重试；导航未读数 30s 轮询（I3 换 WebSocket）。
3. 换头像不清理旧文件；`statistics` 使用 MySQL `VALUES()` 语法（8.0 支持，9.x 前需改 alias）。
4. 管理端题库「全部分类」包含顶级分类，应只列二级（I5 polish）。
5. 登录数按 `last_login_at` 聚合（非逐次登录日志，与原项目同口径）。
